# Эмулятор языка оболочки ОС

Учебный проект (ИКБО-41-25, Вариант №25). GUI-эмулятор командной
строки на Python + PySide6.

## Методология разработки

Проект ведётся поэтапно по методичке (Вариант №25): каждый этап
задания — это отдельный набор фич, зафиксированный отдельными
коммитами, а не один большой коммит в конце.

- **Инкрементальная разработка.** Функциональность добавляется
  шаг за шагом (сейчас реализованы этапы 1–4: REPL, конфигурация,
  VFS, основные команды), каждый шаг — рабочее и протестированное состояние
  программы.
- **Разделение логики и интерфейса.** Разбор команды
  (`parse_command`), её выполнение (`run_command`) и вся работа с
  файловой системой (`src/vfs.py`) не зависят от Qt/PySide6. Это
  позволяет тестировать основную логику без запуска графического
  окна.
- **Юнит-тестирование.** Для логики написаны тесты (`pytest` или
  `unittest`), которые гоняются в headless-режиме
  (`QT_QPA_PLATFORM=offscreen`), поэтому их можно запускать и в
  CI, и без дисплея.
- **Git-флоу.** Коммиты атомарны и подписаны в стиле Conventional
  Commits (`feat(...)`, `fix(...)`) — по сообщению коммита видно,
  какой этап или какая правка в нём сделаны.

## Этап 1 — REPL

- окно с логом диалога и строкой ввода;
- заголовок окна вида `Эмулятор - [user@host]`;
- простой разбор ввода на команду и аргументы (`parse_command`);
- команды `ls`, `cd` и `exit`;
- сообщение об ошибке, если команда неизвестна.

## Этап 2 — конфигурация

Параметры командной строки:

- `--vfs ПУТЬ` — ZIP-архив с виртуальной файловой системой;
- `--script ПУТЬ` — стартовый скрипт: команды выполняются построчно,
  как будто их вводит пользователь (пустые строки и строки,
  начинающиеся с `#`, пропускаются; после `exit` скрипт
  прекращается).

При запуске эмулятор печатает заданные параметры (`[config] ...`).

## Этап 3 — VFS

- VFS целиком хранится в памяти (`src/vfs.py`). Архив только читается:
  ничего не распаковывается на диск и не изменяется.
- Дерево строится по записям ZIP; каталоги, которых нет в архиве
  отдельными записями (только как часть путей `a/b/c.txt`), создаются
  автоматически.
- Содержимое файлов хранится как `bytes`; для двоичных данных есть
  `VFS.read_base64(путь)` — содержимое в base64.
- Текущий каталог показывается в приглашении: `/docs> ls`.
- `ls [путь]` — содержимое каталога (у каталогов в конце `/`) или
  имя файла; `cd [путь]` — смена каталога, `cd` без аргумента — в
  корень. Поддерживаются абсолютные и относительные пути, `.` и `..`
  (выше корня подняться нельзя).
- Ошибки (нет такого пути, `cd` в файл, лишние аргументы, неизвестная
  команда) выводятся в лог, эмулятор продолжает работу.
- Если `--vfs` не указан или архив не открылся (нет файла, не ZIP,
  повреждён), в лог выводится сообщение, а эмулятор работает с пустой
  VFS (только корень `/`).
- Ограничение: аргументы разбиваются по пробелам, поэтому пути с
  пробелами в именах пока недоступны.

## Этап 4 — основные команды

- `ls [путь]` и `cd [путь]` работают на VFS (см. этап 3).
- `pwd` — печатает текущий каталог VFS; аргументов не принимает.
- `history [N]` — нумерованный список введённых команд (нумерация
  сквозная, как в bash); с аргументом `N` показываются только
  последние `N` команд. В историю попадают все непустые вводы, в том
  числе неудачные команды, сам `history` и команды из стартового
  скрипта; пустые строки не записываются.
- Ошибки: аргументы у `pwd`, больше одного аргумента у `history`,
  `history` с нечисловым или отрицательным `N` — сообщение в лог,
  эмулятор продолжает работу.
- Стартовый скрипт этапа: `scripts/start_stage4.txt` — все команды
  этапа во всех режимах, включая работу с VFS и ошибки. Запуск:
  `./scripts/test_vfs_deep.sh scripts/start_stage4.txt` (скрипт не
  заканчивается `exit`, окно остаётся открытым).

## Установка и запуск

```bash
pip install -r requirements.txt
./run.sh --vfs путь/к/архиву.zip --script путь/к/скрипту.txt
```

Оба параметра необязательны. Относительные пути считаются от текущей
папки терминала.

## Скрипты для проверки (`scripts/`)

Каждый `test_vfs_*.sh` создаёт во временной папке ZIP-архив командой
`zip` и запускает эмулятор с ним. Нужен установленный `zip`; другой
интерпретатор Python можно задать так: `PYTHON=python3.13 ./scripts/...`.

| Скрипт | VFS | Стартовый скрипт |
| --- | --- | --- |
| `test_vfs_minimal.sh` | один файл `hello.txt` | `start_minimal.txt` |
| `test_vfs_files.sh` | несколько файлов, в том числе двоичный; архив без записей о каталогах | `start_files.txt` |
| `test_vfs_deep.sh [скрипт]` | вложенность до 4 уровней, пустой каталог | `start_all.txt` (по умолчанию) или `start_stage4.txt` |
| `test_vfs_errors.sh` | нет архива / не ZIP / нет `--vfs` (три запуска подряд) | `start_errors.txt` |

`scripts/start_all.txt` — общий стартовый скрипт: все команды этапов
1–3 во всех режимах, включая работу с VFS и обработку ошибок. Он
заканчивается командой `exit`, поэтому окно закрывается само; чтобы
рассмотреть результат, временно удалите последнюю строку.

## Тесты

```bash
QT_QPA_PLATFORM=offscreen python3 -m pytest tests -v
```

## Структура

```
src/main.py     — окно эмулятора, разбор и выполнение команд
src/vfs.py      — VFS в памяти на основе ZIP-архива
scripts/        — скрипты реальной ОС и стартовые скрипты эмулятора
tests/          — тесты
```
